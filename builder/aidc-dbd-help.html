Install and update

AIDC DBD installs with AIDC-DBD-Setup-<version>.exe. It needs Windows 10 or 11, 64-bit.

Install

  1. Check the download against the release's SHA-256 (optional, recommended): 
    Get-FileHash "$env:USERPROFILE\Downloads\AIDC-DBD-Setup-<version>.exe" -Algorithm SHA256
  2. Run AIDC-DBD-Setup-<version>.exe. The installer is unsigned, so Windows SmartScreen may show "Windows protected your PC": click More info, then Run anyway.
  3. Choose Only for me: it needs no administrator rights. (Anyone who uses this computer installs for every user and asks for administrator rights.)
  4. Keep the suggested folder (for Only for me, %LOCALAPPDATA%\Programs\AIDC DBD) or choose another, then Install.
  5. The installer adds an AIDC DBD shortcut on the desktop and in the Start menu. Start the app from either.
  6. Check Help > About AIDC DBD: it shows the app version, the builder version and the builder's SHA-256.

Update

  1. Save your design and close AIDC DBD, including any DC Layout Builder windows. A running window keeps the version it was started with.
  2. Run the new AIDC-DBD-Setup-<version>.exe. It replaces the installed version in the same folder; the shortcuts keep working.
  3. Check Help > About AIDC DBD.
Keep each release's Setup file: it is your copy of that version. To go back, close the app and run the older Setup file.

Uninstall

Windows Settings > Apps > Installed apps > AIDC DBD > Uninstall. Your project folders are not touched.

Portable zip (where installing is not allowed)

Each release also has AIDC-DBD-<version>-win-x64-portable.zip. Unzip it into a folder of its own and run AIDC DBD.exe from that folder; for a shortcut, right-click the .exe > Send to > Desktop (create shortcut).

Do not copy AIDC DBD.exe out of its folder: it needs the resources folder, the DLLs and the other files beside it.

Load the input sheet

The input sheet sets the design in one step from the customer's values.

  1. File > Input sheet template (blank) saves the template, generated from the builder's catalog. Input sheet filled from this design saves one filled from the open design. In a browser, the toolbar's Input sheet button does the same.
  2. The customer fills it in. The app reads .xlsx or a CSV with the columns key,value,unit,source. It does not read .txt.
  3. File > Load input sheet… reads it. A meter shows each step: reading the file, reading the sheet, applying the settings, building the design, drawing, checking the result. If a step fails, the status line names it and the open design is put back.
  4. The import report lists every row. Download session input file saves the record; it is also saved to the project folder.

Import report statuses

StatusMeaning
appliedThe value was set as given. A model named without its vendor (for example SN5610 for NV-SN5610) is applied with the note "read as".
derivedThe platform has one value for this row and the sheet matches it (for example the GB300 NVL72's BlueField-3 B3240).
nearest supportedThe value is not an offered option, so the design is built at the nearest one. Listed as a design choice.
not supportedThe platform has no such choice, or builds with a different fixed value; the reason column says which.
not modeledThe builder does not model this row. It is recorded, not built.

Build the design

  1. Set Customer and Code, the Fabric platform, the back-end planes and platform, and the front end, or load the input sheet.
  2. Enter Total racks and click Build from rack count.
  3. Render and FE Render draw the back end and the front end; BoM, Config, Infra, Facility, Cable Matrix, Day-2 SoT and Physical model give the views and exports.
  4. Save writes the design file; Load opens one.
After you change a setting that changes the design (platform, planes, switches, pod size), click Build from rack count again. When the rack box and the canvas disagree, the status line says "box says N, model has M — click Build".

Storage on rack-scale platforms (NVL72) is sized per scalable unit, the platform's 8-rack unit. Floor columns arrange whole halls side by side; they do not split the rows inside a hall.

Read the health verdict

The Fabric health panel and the Release check show one line: Errors (N) / Open inputs (N) / Advisories (N).

CountMeaningWhat to do
ErrorsThe design as built is not consistent: a port over-allocation, a rack over its feed, addresses outside their block, a facility load over the stated feed.Fix before delivery.
Open inputsA value is still a placeholder.Get the value from the customer. Never counted as an error.
AdvisoriesThe design is consistent, but a choice or a vendor figure needs confirming (oversubscription, an unconfirmed optic, margin).Review, and record the decision.

On large designs the out-of-band rows wait until the links are counted: click count links in the panel. Past 512 racks the design service counts them.

Release check and delivery build

  1. Open Release check. Clear every error and record the open inputs and advisories.
  2. Use the Site build menu:
Site build menuWhat it does
Final package and .run (with the parity check)Builds both, then checks that every device configuration in the package is byte-identical to the .run's. This is the delivery build.
Final package / Review package (watermarked) / .run onlyOne output.
DC Layout BuilderThe layout tool.
Export site-runner fileThe file for the command-line site runner on another machine.
Show DSX Air test files…Takes air/ out of a .run (checksum verified) into <run name>-air/, for the DSX Air import.

Each job writes to its own folder in the project folder, {BUILD}-{job}-{date-time}/, with the package or .run, the site-runner file it was built from and site-runner.log.

The .run is the installer for the provisioning host. It is not a customer deliverable.

Gates

  • Release gate: the site runner refuses a design exported from a different builder file (its SHA-256 differs). Export the site-runner file again from this release.
  • Fingerprint gate: the site runner and the Layout service rebuild the design from its settings and refuse unless it matches the window's. A mismatch means the canvas was built before a setting changed, or has hand edits.

Equivalence and the Baseline

The equivalence report compares the customer's own design (their Baseline) with the Product's.

  1. File > Baseline template (blank) or Baseline filled from this design saves AIDC-DBD-Baseline-v1.xlsx.
  2. File > Load Baseline… reads the filled Baseline (.xlsx or CSV key,value,unit,source), lists rows it cannot use, and opens the report.
  3. The report shows one row per metric: Baseline, Product, delta, within tolerance, class and reason. A class can be overridden with a reason.
  4. Download report saves <build>-equivalence.pdf and .csv; the status line gives each file's SHA-256.

Topology metrics must match exactly; counts are within tolerance when they differ by no more than 2%.

DC Layout Builder

The layout tool places cabinets in rows and halls, measures every cable run and gives the length schedule and floor drawings.

  • Halls: the dashed outline around a group of rows is a data hall, sized by the Hall MW setting. The outline follows the rows when you move cabinets or change the floor columns.
  • Floor columns (Designer toolbar) arrange whole halls side by side. A site with three halls or fewer looks the same at 3 and 4 columns.
  • Refresh from Fabric Designer takes the design as the builder window has it now and keeps your edits. Change a setting in the Designer, then refresh the layout window.
  • Faceplates: each switch's front panel shows its ports, with the breakout this design uses. A label marked CONFIRM is drawn from a source that does not state it (for example cage numbering read from an LED legend); ports labeled by type only are not cabled by the design.
  • Save layout writes the cabinets, devices and your edits. On a large site the file holds no links; they come from the design when the layout is opened again.

Reset and save

Reset starts a new design. It asks first: Save first, Reset or Cancel.

  • Cleared: every setting, the customer, code and build ID, Device IDs, Public IPs, tenants, site parameters, imported values, deviations you added, layout edits, the input sheet and Baseline records, and the saved copy in this window.
  • Kept: the tuned-profile library and the project folder.

Save the design before you Reset or close the app.

Tuned profiles

A tuned profile is the back-end lossless tuning measured on a site after it passed acceptance, exported by the Deployment Console for one switch model and OS release. Import it with Tuned profiles; later designs on the same switch model and release ship with the measured values instead of the starting defaults. A design can follow the library, pin one profile or use none.

A profile holds the switch model, OS, release, the numeric tuning values and a test summary, with a checksum. It holds no hostnames, addresses or counters. Reset keeps the library.

  1. Make a stand-in CSV with the columns key,value,unit,source, for example: 
    key,value,unit,source

fabric.platform,GB300 NVL72,,dry run
fabric.be.planes,4,planes,dry run
platform.be_switch,NV-SN5610,,dry run
  2. File > New project folder…, then Load input sheet… with the CSV.
  3. Release check, then Site build > Final package and .run.
  4. For a lab rehearsal, Site build > Show DSX Air test files… gives the files for the DSX Air import.
  5. Finish with the deletion drill: delete the dry-run folders as you would a customer's.
